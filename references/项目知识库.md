# 项目知识库建设与使用

> 触发：建立、维护项目知识库，或用户问怎么读/怎么建。未命中禁止读本文件。

## 适用范围

项目长期说明书；不是会话交接，也不是产品客服知识库。

## 何时建立

项目满足以下任意两项时，建议建立项目知识库：

- 预计持续维护超过 1 个月；
- 包含多个端、服务或外部依赖；
- 会被多个开发者或 AI 反复接手；
- 需求、测试或排障资料持续积累；
- 仅看 README 无法快速理解项目。

一次性脚本、临时验证项目和资料不会持续积累的项目，不建立。

## 建立流程

1. 识别项目是否达到门槛。
2. 向用户说明满足的条件，并询问是否建立。
3. 用户确认后，在项目根目录创建 `项目知识库/`。
4. 创建 `项目知识库/00-index.md` 作为唯一入口。
5. 只创建已有实际内容的文档，不创建空文件。
6. 在项目 `AGENTS.md` 中加入一条按需读取指针。
7. 检查索引、文档链接和项目规则中的路径均已同步。

用户未确认前，不自动创建目录或修改项目规则。

## 推荐目录

`00-index.md` 必有，其余按已有内容命名，不预建空文件。文件名可以沿用项目已有命名。

## AI 读取方式

项目 `AGENTS.md` 中使用以下指针：

> 当任务涉及架构、业务规则、接口、数据模型、页面影响或历史决策时，先读取项目根目录 `项目知识库/00-index.md`，再按索引读取相关文档；普通单文件修改不读取整个项目知识库。

读取规则：

- 先读 `00-index.md`；
- 再读取与当前任务直接相关的文档；
- 不因普通单文件修改而全量读取；
- OpenSpec 等已有流程按项目配置读取；
- 关键结论以代码、配置和已确认资料为准。

## 内容边界

- `AGENTS.md`：必须遵守的项目规则；
- `项目知识库/`：稳定事实、业务规则、决策和可复用经验；
- `changes/`：具体需求的方案、规格和任务；
- 《会话交接.md》：当前任务进度、环境状态和下一步；
- 测试归档：正式测试交付物；
- 系统级规则：所有项目共用的约束。

同一条事实只保留一个权威来源。环境中可以直接查到的一次性信息，不重复复制到知识库；只有查找成本高、原因不明显或包含项目约定的信息才记录。

知识库不写入密码、Token、验证码或其他敏感信息。

## 文档维护

每个知识文档开头标注：

```markdown
> 最后更新：YYYY-MM-DD
> 状态：已确认
> 来源：代码 / 需求确认 / 线上验证
> 维护人：姓名或角色
```

发生架构、业务规则、页面、接口或决策变化时更新相关文档；新增、删除或改名时同步更新 `00-index.md`。定期删除失效内容，并保留当前有效结论。

## 完成标准

- 项目根目录有 `项目知识库/`，且 `00-index.md` 能指向所有实文件；
- 项目规则含按需读取指针；
- 无空文档、失效链接或重复权威内容。
