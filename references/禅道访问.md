# 禅道访问

> 触发：打开或登录禅道、在禅道中查看或操作、周报对账、提缺陷单。未命中禁止读本文件。

- 地址：`https://zentao.njsyue.com/zentao/`（开源版 21.7.1）。旧写法 `http://zentao.njsyue.com:8900/zentao/` 已停用，实测连不上。
- 优先复用 Chrome 调试端口 `9222` 上已有登录态；失效时用本机已保存凭据重登并勾选“保持登录”。
- 页面内容可能在子框架（如 `app-my`/`app-execution`），读取时需进入对应 frame。
- 核对进度时以禅道为准，只读。用户告知已完成的项先核实，核实不到的以用户说明为准。
- **默认只读**：查看/读取（任务、需求、用例、缺陷、进度等）直接做。写入或修改（创建/编辑/删除、导入 CSV、变更状态/指派/截止时间、评论备注、批量操作、上传附件等）须先说明具体动作，用户确认后再做。

## 提单通道（用户已授权提单后）

zin 表单组件不吃合成事件，也没有经典渲染入口，用浏览器逐个点填单走不通。改成带当前会话 cookie 直接 POST `bug-create-{产品ID}-0.html`（multipart 一并带附件）；cookie 运行时从已登录会话取，不写进任何文件。

- 字段取值先读页面：模块树、影响版本、严重程度、Bug 类型都只有该产品已配的那几项，凭印象填会报错或掉回默认值。
- `fileList` 字段不要传：会在 `file/model.php` 抛致命错误（缺陷记录其实已建好，只是响应报错，容易误判成提单失败）。
- **图要内嵌在正文**（`<img src="/zentao/file-read-{文件ID}.png">`），只挂附件等于要人下载才看得到。做法：建单时随 `files[]` 上传 → 打开 bug-view 按 `id="fileTitle{N}"` 取回文件 ID → 再编辑一次把图和关键响应摘录回填正文。
- 编辑已有单时把 severity / pri / type / story / task 一起重传，缺哪个哪个就掉回默认值。
- 单里引用的每个证据文件先确认真在磁盘上；会话过期补不回来的图删掉该引用，改用接口 JSON 作证。
