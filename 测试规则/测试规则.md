# 〇、写用例铁律（开写 JSON 前）

**材料先于用例。** 覆盖表和测试 manifest 之前，把本任务/需求给出的材料全部打开看完：需求文档（飞书/GitLab/本地 md）、前后端评审、流程图、Figma/UI。有 Figma 链接或文件：先按系统级触发表登录，再对照每一页/每一帧。完成时已有材料核对表：每份材料标记已读，缺失项标记「受阻：原因」；每个成功标准都能追溯到材料位置。

**归档先认产品。** 写用例前先按触发表读 `references\禅道访问.md`，再看禅道「所属产品」。路径 `D:\测试用例\{所属产品}\{YYYYMMDD}\{需求名-负责人}\`；根下没有该产品文件夹则新建。细则：`测试用例交付与归档.md`。

先完成覆盖表 A/B/C，再写测试 manifest。**A 列按需求「成功标准 / 不满足判定 / 本期验收」逐条落到稳定用例键或「受阻：原因」**；B 列沿用旧规则；C 列现网已有入口。完成时 A/B/C 每行均有稳定用例键或受阻原因。细则：`测试用例设计规范.md` §1.2。

**移动端 = iOS、Android、H5、小程序**，WAP 是 H5 的别名。四端默认全测、各自成组。只有需求/飞书/评审原文点名某一端「不测 / 不做 / 本期不改」才跳过该端。「移动端」三字、入口清单只有 H5、本机无包，都不是跳过理由；无包/无源码仍建条。四端执行都走**真机配合**（用户手机无法测该端才标受阻）。触及 PC 则 PC 另组。细则：`测试用例设计规范.md`「端口成组」；执行：`真机配合.md`。

用户给出同事表或另一份用例表，要求对照覆盖、看区别、看要补充：先出覆盖对照 xlsx（桌面 + 归档日期目录，不进四件套），再按缺口补现行用例。细则：`覆盖对照表.md`。

执行时：前置主功能已失败且后续步骤做不下去，依赖条使用 `blocked_dependency`（展示为「前置依赖受阻」）并跳过，不另开 BUG；不依赖该能力的条照常测。细则：`测试执行精进规则.md`。

## 测试数据创建与保留

- **创建前必须先确认**：数据名称、字段值、用途、所在页面、影响范围完整告知，并询问“是否直接在测试环境中新建”；确认后才执行。
- **创建后保留**；清理仅在用户明确要求时进行。
- **可识别可追溯**：新建数据命名 `wwd_` + 日期（如 `wwd_20260813_商品`），项目级可改前缀；登记项目《测试数据台账.md》附查看路径；存量旧命名数据同步改名/重建属写入操作，先确认。
- **创建后主动汇报**：名称、页面/接口、状态、查看路径，必要时附截图。
- **修改他人创建的数据、影响共享数据或正式流程**，先说明、经用户同意后执行。

## 测试环境多端自动登录

- 按项目级 `AGENTS.md` 或 `.cursor/rules/` 中《测试环境入口清单》顺序依次登录；登录态有效直接复用。
- 过期按清单顺序逐个重登；每端先图形验证码、确认后触发短信、再索取短信验证码，**不要乱序、不要一次性索取全部验证码**。
- 只读查看不受登录限制；写操作仍遵守上文《测试环境操作》。

## 验证码获取与发送（固定方法，不再试错）

1. 图形验证码取图：页面内 `fetch(验证码URL)` → `arrayBuffer` → `btoa` 保存 PNG；页面内 base64 `img` 直接取 `dataURL`。
2. 放大：Python PIL 8 倍 LANCZOS（脚本若存在：`%USERPROFILE%\.codex-build\upscale.py` 或项目内 `.codex-build/upscale.py`），只放大不裁剪。
3. 图形验证码识别：模型自行识别并填写，最多 **3 次**（填错或过期则刷新换图再识）。前 3 次不要把图发给用户。
4. 3 次都没对：再把当前放大后的验证码图用 Markdown（正斜杠绝对路径）发给用户，等用户回填后填入；取不到独立验证码图时再整页截屏。用户回填后若仍错/过期，重新取图，再从第 3 步走（先自己识 3 次）。不换别的取图方式。
5. 短信验证码：触发发送成功后直接向用户索取，填入登录。不要求用户先认图形验证码。

## 微信开发者工具与小程序辅助自动化

- 小程序用例以 `真机配合.md` 为主流程；开发者工具只用于后台准备、辅助定位和取证，不替代用户真机确认。
- 辅助自动化需要：微信开发者工具 + 用户微信扫码登录工具 + 设置-安全设置开启「服务端口」+ 小程序 appid 或源码目录。
- 服务端口以工具设置中的实际端口为准（不默认 9420）。
- 无源码时直接走真机配合，不标环境受阻。
- 自动化插件 `miniprogram-automator`；CLI：`cli.bat auto --port <端口> --project <源码路径>`、`cli.bat open --project <路径>`。
- 辅助自动化涉及写入或数据变更时，按上文《测试环境操作》先说明、经用户同意再执行。
