# 交付门禁铁律（宣称完成前）

任何测试交付（四件套、执行结论、BUG 反馈）宣称完成前，必须运行现有生成器的校验命令，完成条件是它输出以 `ok:` 开头且退出码为 0：

```
python %USERPROFILE%\.codex\测试规则\scripts\generate_test_package.py --check <需求归档目录>
```

非 `ok` 时按报错项修复 `source/manifest.json` 或产物，重跑同一条命令直到 `ok`。未到 `ok` 只能报「未通过校验：原因」。校验范围见 `测试用例交付与归档.md` §二。

# 〇、写用例铁律（开写 JSON 前）

**材料先于用例。** 覆盖表和测试 manifest 之前，把本任务/需求给出的材料全部打开看完：需求文档（飞书/GitLab/本地 md）、前后端评审、流程图、Figma/UI。有 Figma 链接或文件：先按系统级触发表登录，再对照每一页/每一帧。完成时已有材料核对表：每份材料标记已读，缺失项标记「受阻：原因」；每个成功标准都能追溯到材料位置。

**归档先认产品。** 写用例前先按触发表读 `references\禅道访问.md`，再看禅道「所属产品」。路径 `D:\测试用例\{所属产品}\{YYYYMMDD}\{需求名-负责人}\`；根下没有该产品文件夹则新建。细则：`测试用例交付与归档.md`。

先完成覆盖表 A/B/C，再写测试 manifest。**A 列按需求「成功标准 / 不满足判定 / 本期验收」逐条落到稳定用例键或「受阻：原因」**；B 列沿用旧规则；C 列现网已有入口。完成时 A/B/C 每行均有稳定用例键或受阻原因。细则：`测试用例设计规范.md` §1.2。

**移动端 = iOS、Android、H5、小程序**，四端默认全测。跳过某端须需求原文点名。无包/无源码仍建条；执行走真机配合。细则：`测试用例设计规范.md`「端口成组」；执行：`真机配合.md`。

用户给出同事表或另一份用例表，要求对照覆盖、看区别、看要补充：先出覆盖对照 xlsx（桌面 + 归档日期目录，不进四件套），再按缺口补现行用例。细则：`覆盖对照表.md`。

**执行与开缺陷。** 见 `测试执行精进规则.md`（含 `blocked_dependency`、开缺陷口径、**字面**判定）。

**字面。** 端点值、失败后再保存、保存后控件仍在。写步骤：设计规范 §4.11；判定：执行精进 §五第 12 条。
