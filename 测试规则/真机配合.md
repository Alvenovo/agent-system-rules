# 真机配合（Android / iOS App 执行）

> 触发：执行 Android/iOS App 用例、真机配合、用户在手机上操作。
> 节奏与证据数量仍受《测试执行精进规则》硬上限约束；本文件只定线上/手机分工。

## 分工

| 侧 | 谁 | 做什么 |
|---|---|---|
| **线上** | 模型 | CDP/脚本改后台配置、保存、核列表/接口。后台步骤不交给用户。 |
| **手机** | 用户 | 按**手机卡**打开指定页，对照「应当出现」看对不对。 |

完成标准：卡上已写可核对的结果；用户说对即该步通过，说不对才记实际。PC 上无测试包不是受阻；受阻仅当用户声明该端本次无法测（未装包 / 装不上 / 不测）。

线上优先复用项目 CDP 已登录态；能接口改的走该项目自动化目录 `tests/`；不能接口改的用浏览器操作后台。新探针放工作区 `.codex-build/`，不另起框架。首次改共享 SKU 先点名对象；用户说「开始测」即同意本需求已写明的测试链接改动。

## 步骤

1. **线上配本条数据。** 完成：列表或接口已是本条前置；SKU、商品名写进手机卡。
2. **出一张手机卡，然后停。** 完成：用户能打开对的商品，按「应当出现」自行对照。一次一张卡（可含本条连续 2–3 步）；用户说对或说不对后再出下一张。
3. **按对照结果判定。** 完成：说对 → 通过；说不对 → 记下实际，必要时请 1 张现场图再定性。对的步不向用户要截图、不要字段清单。
4. **要换配置时先改线上，再出下一张卡。** 完成：手机上不会看到上一档残留配置。
5. **该端 App 条全部判定后再回写状态清单。** 完成：与精进规则「交付收口一次完成」一致；过程中进度只写《会话交接.md》。

## 手机卡

每张卡固定这些行，缺一行就未完成：

- **用例**：编号 + 本步在测什么（一句话）
- **请打开**：App（华硕商城 / 会员商城）+ 商品名或 SKU
- **请看**：位置（原「京东」字样处 / 绿色浮层 / 弹窗 / 跳转页）
- **请点**：无则写「不用点」；有则写按钮文案
- **应当出现**：可直接对照的结果（渠道名是「天猫」；有绿色浮层；跳转打开 `https://…`）。写判定原文，不写「展示正确」。

Android 与 iOS 分开出卡。

用户侧默认只回一句：**对** 或 **不对 + 实际看到什么**。不对时才要图。

## 证据

- 通过：用户说对 + 线上配置或接口 1 份。
- 缺陷：用户说的实际结果；定性需要时再加现场 1 图。
- 通过不采手机截图，也不把通过图读进模型。
