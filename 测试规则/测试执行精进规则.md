# 测试执行精进规则（通用，系统级）

> 触发：执行测试用例、跑自动化/脚本复验、采集/归档执行证据、判定通过或缺陷、回写执行状态前，**必须先完整读取本文件**再执行。  
> 目的：在保证结论可复核的前提下，控制轮次与 token；与《测试用例交付与归档》配合——归档结构仍按后者，**证据数量与执行节奏按本文件硬上限**。

## 一、硬上限（默认必须遵守）

| 项 | 上限 |
|---|---|
| 证据（通过用例） | 每条 **1 份**关键凭证即可（优先接口 JSON：请求参数 + 响应命中结论）；**默认不截图** |
| 证据（缺陷用例） | 每条 **≤2 份**：1 张页面截图（筛选条件/操作现场 + 失败列表）+ 1 份接口 JSON；够定性即停 |
| 全任务通过样例截图 | **≤2 张**（证明判定方法成立即可，如 1 个对照模块） |
| 同一任务有效全量执行 | **≤1 次**；脚本自身故障或错误环境造成的无效运行不计，修正后重跑；有效运行失败后只复跑失败项 |
| 脚本 stdout | 每条用例 **≤1 行**结论（模块 \| 状态 \| 一句话原因）；详情落盘 |
| 读图进模型 | 接口、日志和结构化结果不足以定性视觉问题时，读取最多 1 张关键图 |
| 新建测试数据 | 只读扫描确认确无可用数据 **且** 用户已授权后，才建 **1 条**最小数据 |
| 表单/入口探测 | 同一操作最多试 **2** 种定位方式；仍失败则停下说明，禁止连续堆探针脚本 |
| 未执行盘点 | 执行前 **1 次**脚本抽出「未执行」编号+标题；禁止为找剩余条翻产品全表 `innerText` |
| 单条超时 | 默认 **≤30s** 墙钟；长异步流程在 manifest 显式声明 `timeout_seconds`；超时记结论并继续下一条 |
| 前置失败的硬依赖条 | **不执行**、不取证、不单开 BUG；状态用 `blocked_dependency` |

## 二、执行节奏

1. **先单模块打通判定，再全量**  
   用 1 个对照模块验证：操作 → 抓包/取证 → 判定逻辑。跑通后再扫全模块。

2. **脚本调试 ≠ 用例执行**  
   取列错误、反向搜索未重置、截图超时、定位不稳定等，在单页探针里解决，禁止塞进全量循环边跑边修。  
   日期控件、富文本工具栏、文件上传先单独探针跑通（≤10s），再进全量。校验类（空/超长）与创建类、视觉类分批。

3. **先只读扫描再动手**  
   先确认：筛选项/列是否存在、有无数据、关键字段是否为空。有数据绝不新建；没数据再按授权建最小数据。  
   **禅道未执行**：走「仅场景」或从页面 dtable 源码（`&quot;` JSON）按场景名 / `lastRunResult` 过滤。需求页「相关用例 0」不代表没用例。已有列表数据命中该条预期 → 核对通过，不重复新建。

3.1 **能验完就验完**  
   本条预期在当前环境做得到 → 做到通过或疑似缺陷。缺用户动作（真机按卡、验证码、造数授权、关闭占用的 xlsx、看现场拍板）→ **停下，直接写要用户做什么**，等回复后再判定。用户明确本轮不测或无法配合 → `blocked_environment`（该端单独受阻；已验完的端标通过）。

4. **缺陷定向复验单独做**  
   疑似缺陷用独立小脚本复验 **1～2** 次即可定性，不夹在全量脚本里反复重跑。

5. **状态逐条落源，交付一次收口**
   每条判定后原子更新 `source/manifest.json`，避免中断丢进度；执行过程中不重建四件套。全部跑完后统一生成状态清单、证据清单、BUG 文档和执行过程，并更新会话交接。

6. **前置阻断：主功能失败则硬依赖条立刻跳过**  
   某条已判定失败（疑似缺陷），且后续条的步骤**做不下去**（缺入口、缺该能力、缺该条产出的数据）：后续条使用 `blocked_dependency` 并跳过。实测说明引用前置 `case_key` 并写明缺少的条件。
   - 只跳过硬依赖。不依赖该能力的条照常测，禁止一条失败停整表。  
   - 跳过条展示为「前置依赖受阻」，未跑过的不算新缺陷。
   - BUG 只出根因那一份；跳过条在说明里引用该前置编号/BUG，不按跳过条拆单。  
   - 前置修复合入后：只复跑该前置条 + 曾因它受阻的条（与「全量 ≤1 次」一致）。  
   例：引用功能未实现 → 所有「先引用再回复/取消/多端同步」的条受阻跳过；不引用也能测的条继续跑。

## 三、证据采集

1. **求精不求多**（与《测试用例交付与归档》一致，本处给出数量硬上限）：  
   - 通过：接口/DB/日志中 **1 份**能区分通过的凭证即可。  
   - 缺陷：页面失败现场 **1 图** + 接口/日志 **1 份**即可。  
   - 禁止“每条用例全量截图”。

2. **截图时机**：仅在最终定性缺陷或需要 1～2 张对照通过样例时截图；调试阶段不截图。

3. **证据落盘**：路径、文件名和 `证据/实测证据清单.md` 由生成器按《测试用例交付与归档》写出。本处只管数量上限。

4. **共享证据**：同一证据只落盘一次，在 manifest 的 `evidence[].case_keys` 关联所有适用用例。

## 四、输出与上下文（省 token）

1. 脚本只打印一行结论；完整请求/响应、DOM 快照写入证据目录，**禁止**把整页 `innerText`、完整接口 body 打到 stdout。  
2. 需要看证据时**按字段读**（如 `status / note / requestHasId / responseAllMatch`），禁止整文件吞进对话。  
3. 探针脚本只返回：按钮文案、label、路由/是否弹层；禁止大段页面文本反复回吐。  
4. 截图默认只落盘给人看；不主动把 PNG 读进模型上下文。

## 五、判定与缺陷定性

1. **判定标准先写死、用对照模块测通再全量**。典型：筛选项存在 + 请求带关键 ID/参数 + 响应全部命中 + 列显示正确（如需求要求）。  
2. **GET query 与 POST body 都要验**，漏一种会导致假阴/假阳。  
3. **部分验证是窄口。** 一部分预期已经证完、剩下的确定做不了、且不是在等用户时，才用 `partial`，说明里写清已证 / 未证。缺配合、步骤没做完、缺数据但用户还没拒绝协助，都先按 3.1 做完或停下问。  
4. **数据缺失 ≠ 功能缺陷**：先建 1 条最小数据做正向命中，再区分是筛选失效还是列不展示。  
5. **BUG 文档按缺陷条数写**，不按用例条数拆多份；每条缺陷附 ≤2 份关键证据路径即可。前置失败导致跳过的条不另开 BUG，归入根因那一份。
6. **因前置失败跳过的条使用 `blocked_dependency`**。根因条才用 `suspected_defect` 并取证。
7. 复验 1～2 次后仍无法定性，或属于性能退化、偶现和跨服务问题时，读取并执行 `%USERPROFILE%\.codex\skills\诊断缺陷\SKILL.md`。
8. **开缺陷先对需求原文。** 预期写飞书/禅道可定位位置。同事表、推断不当成功标准；原文没有的能力不开缺陷。
9. **沿用旧逻辑先对现网旧控件。** `maxlength`、数字框精度与旧字段相同则本期不另开缺陷。脚本给 `input` 赋值绕过 `maxlength` 后的保存，不算人工可复现。
10. **用户端展示按真机配合收口。** 展示/文案/跳转：用户说对才过。BUG「实际」写当时后台配置、接口字段和时间；后续条改过配置则交文档前再复验。
11. **拿不准先给用户看现场，再写 BUG 文档。**

## 六、登录态与探针

CDP 登录态是贵资源。探针只读当前页（hash、按钮、表单 label）。换页用 hash / 菜单点击，不用探针 `goto` 登录页或整站 `reload`。校验拦截看 `.ant-form-explain` 等表单项提示，不只认 toast。超长是否可存：见 §五第 9 条。

## 七、文件与环境小约束

1. 回写 xlsx 遇文件锁（WPS/Excel 占用）时**先停并提示用户关闭**，禁止无意义重试。  
2. 探针脚本和过程文件放项目 `.codex-build/`；`证据/` 只收最终按用例编号命名的关键凭证。正式交付物只写归档目录。  
3. 与项目级 `AGENTS.md` 冲突时：**项目级优先**；本文件管执行节奏与证据数量上限。

## 八、模型分工

> 原则：**模型做「判」和「写」，脚本做「点」和「抓」**。禁止把模型当点击员或整表监控员。

1. **脚本无人值守跑全量；模型不盯日志逐条对话**  
   全量执行用本地 `node`/自动化脚本一次性跑完；模型只启动脚本、等结束、读汇总（stdout 一行结论或结果 JSON 的状态字段）。禁止在长对话里边点边播报每一步。脚本调试在单页探针完成后再全量，禁止边跑边修。

2. **模型深度介入只用于：失败项复验、缺陷定性、交付收口**  
   通过项默认不展开证据进上下文。失败/疑似缺陷：只读该条 ≤2 份关键凭证的关键字段。定性后一次性写：执行状态、证据清单、BUG 文档、会话交接。大量机械改脚本时，可用更快模型改代码，再用当前对话模型做最终判定（可选）。

3. **执行任务优先开干净对话**  
   不要在已经很长的调试会话里接着全量跑。新对话：读项目级规则 →《会话交接.md》→ 命中则读 `测试规则.md` 与本文件 → 按硬上限执行。截图只落盘；默认不把 PNG 读进模型。

4. **真机配合**  
   执行 Android/iOS App、小程序、H5 不套无人值守全量：线上由模型准备数据和辅助取证，手机由用户按卡对照「应当出现」；说对即过，说不对再记实际。WAP 按 H5 执行。细则：`真机配合.md`。
