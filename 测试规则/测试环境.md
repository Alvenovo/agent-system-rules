# 测试环境操作

> 触发：测试环境登录、造数、写入、验证码、多端自动登录。未命中禁止读本文件。

写入/数据变更类操作：动手前先说明具体操作、对象、影响范围、是否需要清理；**用户同意后才执行**；只读查看不受限。测试数据默认保留供校验，不主动清理；清理先提方案，经同意后执行。禅道仍严格只读，除非用户明确要求写回。

## 测试数据创建与保留

- **创建前必须先确认**：数据名称、字段值、用途、所在页面、影响范围完整告知，并询问“是否直接在测试环境中新建”；确认后才执行。
- **创建后保留**；清理仅在用户明确要求时进行。
- **可识别可追溯**：新建数据命名 `wwd_` + 日期（如 `wwd_20260813_商品`），项目级可改前缀；登记项目《测试数据台账.md》附查看路径；存量旧命名数据同步改名/重建属写入操作，先确认。
- **创建后主动汇报**：名称、页面/接口、状态、查看路径，必要时附截图。
- **修改他人创建的数据、影响共享数据或正式流程**，先说明、经用户同意后执行。

## 测试环境多端自动登录

- 按项目级 `AGENTS.md` 或 `.cursor/rules/` 中《测试环境入口清单》顺序依次登录；登录态有效直接复用。
- 过期按清单顺序逐个重登；每端先图形验证码、确认后触发短信、再索取短信验证码，**不要乱序、不要一次性索取全部验证码**。
- 只读查看不受登录限制；写操作仍遵守上文写入确认。

## 验证码获取与发送（固定方法，不再试错）

1. 图形验证码取图：页面内 `fetch(验证码URL)` → `arrayBuffer` → `btoa` 保存 PNG；页面内 base64 `img` 直接取 `dataURL`。
2. 放大：Python PIL 8 倍 LANCZOS（脚本若存在：`%USERPROFILE%\.codex-build\upscale.py` 或项目内 `.codex-build/upscale.py`），只放大不裁剪。
3. 图形验证码识别：模型自行识别并填写，最多 **3 次**（填错或过期则刷新换图再识）。前 3 次不要把图发给用户。
4. 3 次都没对：再把当前放大后的验证码图用 Markdown（正斜杠绝对路径）发给用户，等用户回填后填入；取不到独立验证码图时再整页截屏。用户回填后若仍错/过期，重新取图，再从第 3 步走（先自己识 3 次）。不换别的取图方式。
5. 短信验证码：触发发送成功后直接向用户索取，填入登录。不要求用户先认图形验证码。
