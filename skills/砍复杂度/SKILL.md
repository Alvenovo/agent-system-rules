---
name: 砍复杂度
description: 对着 diff 或指定范围列出可删的过度设计，只列不改。
disable-model-invocation: true
---

只猎过度设计。默认看当前 git diff；用户点名文件或「整仓」则改范围。测试规则要求的覆盖表、四件套、证据目录不要标成可删。

## 格式

一行一条：`path:Lstart-Lend: 标签: 砍什么。换成什么。`

标签：

- `delete:` 死代码、没人用的扩展、臆想功能。替换：无。
- `stdlib:` 手写了标准库已有的。点名那个函数。
- `native:` 平台或浏览器已有。点名那个能力。
- `yagni:` 只有一个实现的抽象、没人改的配置、只有一个调用方的层。
- `shrink:` 同一逻辑，更短写法。写出短的那一版。

## 例子

❌ 「EmailValidator 可能有点复杂，要不要考虑现阶段是否需要这些规则？」

✅ `validate.py:L12-38: stdlib: 27 行校验类。邮箱有 "@" 即可，真校验在确认邮件。`

✅ `ui.tsx:L4: native: 为一次格式化引入 moment。Intl.DateTimeFormat，0 依赖。`

✅ `repo.py:L88: yagni: AbstractRepository 只有一个实现。第二个出现前内联。`

## 完成

按可删行数从大到小。结尾只报 `net: -N 行`（能估依赖则加上 `-D 依赖`）。没有可砍的：`已经够瘦。可提交。` 然后停。

不改代码。对错、安全、性能不是本 skill 的范围；发现则一句转到 `诊断缺陷`，不混进清单。信任边界校验和防丢数据处理不要标成可删。
